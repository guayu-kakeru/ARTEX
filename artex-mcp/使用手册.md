## 2. 启停与日常运维（命令级）

```bat
:: ===== PostgreSQL =====
<PG_HOME>\status-pg.bat                        :: 看状态
<PG_HOME>\start-pg.bat                         :: 启动（输出重定向到文件，别管道给 tail 之类）
<PG_HOME>\stop-pg.bat                          :: 停止

:: ===== ARTEX（必须用 start.bat，守护+支持页面一键更新）=====
cd <ARTEX_HOME>
start.bat                                                      :: 前台启动，Ctrl-C 停止
start.bat -data D:\artex-data                                  :: 产物目录迁到 D 盘（见 §7.4）
start.bat -addr :8787 -proxy 127.0.0.1:8788                    :: 显式指定端口（默认就是这俩）

:: ===== 验证三连 =====
curl http://127.0.0.1:8787/api/health                          :: {"ok":true,...}
curl -X POST http://127.0.0.1:8787/api/auth/login -H "Content-Type: application/json" -d "{\"username\":\"ARTEX\",\"password\":\"<你的密码>\"}"
:: 返回 {"token":"eyJ..."} —— 这个 JWT 后面所有 curl 都要带：
::   -H "Authorization: Bearer <token>"
```

> **为什么必须 start.bat**：退出码 75=换装重启（页面一键更新靠它），其他=崩溃退避重拉。直接跑 `artex.exe` 更新后不会被拉起。

## 3. 快速开始：5 分钟跑通第一个任务

### 3.1 网页方式（最直观）

1. `start-pg.bat` → `start.bat` → 浏览器开 <http://localhost:8787>
2. 首次进 `/setup` 设管理员密码（≥8 位）；之后用户名恒为 `ARTEX`
3. 「LLM 配置」页确认已有可用模型，点「测试连接」应返回 ok
4. 「任务」页 → 新建任务：**描述**填背景，**目标**填 `对 <已授权目标> 做只读侦察`，
   超时填 600 秒 → 创建即自动开跑
5. 任务详情页看：执行过程（活动流）/ 测试资产 / 发现 / 探索链路

在 DSH 里直接说：

```

只读、禁止扫描其他地址、禁止利用，超时 600 秒
```

## 4. 如何给它资产（6 种方式，按场景选）

### 4.1 写在 goal 里（最常用，零操作）

goals agent 会自动从目标文本提取范围并登记 scope。**写法约定**：

| 目标形态 | goal 里这样写 | 自动登记为 |
| --- | --- | --- |
| 裸 IP | `对 10.1.2.3 做端口探测` | kind=ip |
| 网段 | `探测 10.1.2.0/24` | kind=cidr |
| 完整 URL / 子域 | `测 https://a.example.com/path` | kind=subdomain, value=a.example.com |
| 裸根域名 | `扫 example.com 所有子域` | kind=root_domain |

> 约束也要**写进 goal/描述**（agent 自动登记为 deny/allow 约束），写法见 §5.2。

### 4.2 任务级 scope API（建任务后补范围）

```bash
curl -X POST http://127.0.0.1:8787/api/tasks/<任务id>/scope \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"kind":"subdomain","value":"a.example.com","reason":"授权书编号 XXX"}'
# kind: ip | cidr | subdomain | root_domain
# 查看：GET  /api/tasks/<id>/scope      删除：DELETE /api/tasks/<id>/scope/<sid>
# 注意：登记 scope 的同时会将该目标写入资产图（可删资产移除，见 4.3）
```

### 4.3 批量导入资产（适合把现有资产库灌进去）

```bash
curl -X POST http://127.0.0.1:8787/api/assets \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"task_id":12,"assets":[
    {"type":"root_domain","domain":"example.com","icp":"京ICP备xxx"},
    {"type":"subdomain","domain":"a.example.com","record_type":"A","record_value":["1.2.3.4"]},
    {"type":"ip","ip":"10.1.2.3","open_ports":[{"port":443,"service":"https","protocol":"tcp"}]},
    {"type":"service","url":"https://a.example.com","technologies":["Nginx"],"status_code":200,"page_title":"登录"},
    {"type":"service","ip":"10.1.2.3","port":22,"service_name":"ssh"},
    {"type":"app","app_name":"示例App","bundle_id":"com.example.app","category":"Android"},
    {"type":"endpoint","url":"https://a.example.com","method":"GET","params":[]}
  ]}'
```

字段对照：`root_domain`(domain/icp)、`subdomain`(domain/record_type/record_value)、
`ip`(ip/bound_domains/open_ports)、`app`(app_name/bundle_id/category)、
`service`(HTTP 填 url+technologies+status_code+page_title；其他填 ip+port+service_name)、
`endpoint`(url/method/params)。

删除资产：`DELETE /api/assets`，body `{"ids":[<资产id>,...]}`（id 从 `GET /api/assets` 拿）。

### 4.4 公司维度（资产按公司归并，多任务共享）

```bash
# 建公司 + 初始范围
curl -X POST http://127.0.0.1:8787/api/companies \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"name":"XX 系统","scope":[{"kind":"root_domain","value":"example.com"},{"kind":"ip","value":"10.1.2.3"}]}'
# 建任务时带 company_ids（自动快照该公司当前资产进任务）
#   → createTask 传 "company_ids":[<公司id>]
```

### 4.5 挂载已有资产到任务

```bash
curl -X POST http://127.0.0.1:8787/api/tasks/<任务id>/assets \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"asset_ids":[1,25,26],"source_summary":"来自上次扫描"}'
```

### 4.6 从 ScopeSentry 同步（已有扫描平台的团队）

页面「资产同步」页填 ScopeSentry 地址 + API Key，按项目/任务选目标与资产类型一键导入；
或走 API：`POST /api/sync/scopesentry/datasource` → `POST /api/sync/scopesentry/sync`。

> **授权提醒**：不管哪种方式，资产必须在**已书面授权**范围内；§4.1/4.2 的 reason 字段
> 建议写授权依据，便于审计。

### 4.7 公司级资产导入（2026-10-18 实战实测形状）

> 场景：把整个授权项目的资产库灌进公司维度，以后每个任务按公司快照/挂载。实战导入 4080 条（500/批）零失败。

```bash
# 1) 建公司 + scope（注意：公司 scope 只认 kind=domain，root_domain 会被拒）
curl -X POST http://127.0.0.1:8787/api/companies \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"XX 挑战赛","scope":[{"kind":"domain","value":"example.com"}]}'

# 2) 补 scope（body 形状：{"scope":[{kind,value}],"reason":...}，数组包在 scope 字段里）
curl -X POST http://127.0.0.1:8787/api/companies/1/scope \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"scope":[{"kind":"domain","value":"example.com"}],"reason":"授权书编号 XXX"}'

# 3) 公司级批量导资产（task_id 换成 company_id；500 条/批）
curl -X POST http://127.0.0.1:8787/api/assets \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"company_id":1,"assets":[{"type":"subdomain","domain":"a.example.com","root_domain":"example.com","service":{"url":"https://a.example.com","technologies":["nginx"],"page_title":"404"},"note":"来源标注"}]}'
```

**资产类型映射建议**（外部清单 → ARTEX）：域名清单 → `subdomain`（带 root_domain 归并）；探过指纹的 → 附 `service{url,technologies,page_title}`；接口清册 → `endpoint`。**已有资产按 domain 自动归并去重**（重复导入安全）。

⚠ **黑名单陷阱**：往 `redline_rules.json` 的 `domain_blacklist` 加域名前，**先核对该域是否在授权清单内**——实战差点把 `sub.example.com`（在 v2 清单 hunting_queue 里）误加，把自己范围锁了。清单内家族一律不加。

## 5. 创建任务：参数详解

### 5.1 `POST /api/tasks` 全字段（`artex_create_task` 的底层）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 任务名，可空 |
| `description` | string | 任务描述（背景：靶标范围/交战说明），空则“未命名任务” |
| `goal` | string | **目标**：最终可达成结果 + 约束（见 5.2） |
| `llm_profile_id` / `llm_profile_ids` | int / []int | 指定 LLM 配置链；空=用激活配置（当前 step-5-preview） |
| `company_ids` | []int | 关联公司（快照其资产） |
| `source_task_ids` | []string | 继承来源任务（只读引用其资产/发现） |
| `timeout_seconds` | int | 任务级超时，0=不限 |
| `plan_heartbeat_seconds` | int | planner 心跳间隔，默认 600，下限 600 |
| `seed_first_intent` | bool | true=跳过首轮 planner 直接派种子意图（CTF 抢时间用） |
| `coverage_enabled` | bool | 资产覆盖度计算，默认 true |
| `intercept_rules` | [] | 任务级拦截规则（创建时录入） |

### 5.2 goal 写法模板（约束+目标，直接抄）

```
对 <目标> 做 <动作>。约束：仅允许测试 <目标>；禁止扫描或请求 <目标> 以外的
任何地址；只允许 GET/HEAD 只读请求与端口探测；禁止任何写、删、改、上传操作；
禁止登录尝试与爆破；不做漏洞利用。
```

- 约束会被 goals agent 登记成 deny/allow 并注入 planner/worker 提示，**必须写死具体目标**，别写“当前目标”；
- 目标只写**最终可交付结果**（如“输出服务清单并识别每个服务的指纹”），别写攻击步骤——planner 自己会拆。

### 5.3 意图级干预（任务跑起来后）

```bash
# 暂停/恢复任务
curl -X POST http://127.0.0.1:8787/api/tasks/<id>/control -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" -d '{"action":"pause"}'     # 或 resume

# 暂停/恢复/取消单条意图（iid 从 artex_frontier 或活动流里看）
curl -X POST http://127.0.0.1:8787/api/tasks/<id>/intents/<iid>/control \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"action":"cancel","mode":"soft","reason":"超出授权范围，人工叫停"}'
# mode: soft=软删保留血缘（默认）| hard=物理删除
```

### 5.4 换 LLM / 查看用量

```bash
# 换模型（StepFun 其他模型或别家 OpenAI 兼容端点）
curl -X POST http://127.0.0.1:8787/api/llm -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"step-3.7-flash","base_url":"https://api.stepfun.com/v1","api_key":"<key>"}'
# 测试连通：POST /api/llm/test（同样字段，会真发一次最小请求）
# 用量：GET /api/tokens/usage（全局聚合）、/api/llm/records（每次调用明细）
```

## 6. 监控与危险命令防控（三层防线）

### 6.1 第一层：审批门（执行**前**拦截）

页面「系统配置 → 拦截审批 → 工具配置」把危险工具加进审批清单（如 `Bash`、`Write`），
agent 调这些工具前会挂起等人工裁决：

```bash
# 看待办审批
curl http://127.0.0.1:8787/api/intercept/pending -H "Authorization: Bearer <token>"
# 裁决：allowed 放行 / denied 拒绝
curl -X POST http://127.0.0.1:8787/api/intercept/pending/<pid>/decide \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" -d '{"decision":"denied"}'
```

### 6.2 第二层：红线看门狗（执行**后**秒级急停）——重点

```bat
:: 武装看门狗（跑任务前必开，另开一个窗口）
cd <WORKSPACE>\artex-mcp
python artex_watchdog.py --all
```

- 订阅活动流，逐条审查 agent 的每个工具调用；
- 命中红线 → 写 `redline_alerts.log` → **自动暂停任务** → 把审批门挂起项全判 `denied`；
- `--dry-run` 只告警不暂停（新规则上线先试运行）；`--task <id>` 只盯一个；
- 规则在 `redline_rules.json`，默认 5 类 + 域名黑名单：

| 规则 | 抓什么 |
| --- | --- |
| 破坏性命令 | `rm -rf`、`format`、`mkfs`、`dd if=`、`diskpart`、`shutdown`… |
| 凭据窃取/横向移动 | `mimikatz`、`lsass`、`psexec`、`wmiexec`、`/etc/shadow`… |
| 外联回弹/数据外传 | `nc -e`、`/dev/tcp/`、`bash -i`、`curl -T`、`scp`… |
| 数据库直接拖库 | `mysqldump`、`pg_dump`、`into outfile`… |
| 危险提权 | `chmod 777`、`runas /user:administrator`… |

**上线前必做**：把公司生产域名填进 `domain_blacklist`，agent 命令里一出现就暂停：

```json
"domain_blacklist": ["example.com", "sz example.com 的生产域名…"]
```

### 6.3 第三层：事后审计

```bash
# AI 随时抽查（MCP 工具 artex_activity_redline_check，只读）
# 或直接扫历史：
curl "http://127.0.0.1:8787/api/exploration/activity/history?task=<id>&session=plan&limit=200" \
  -H "Authorization: Bearer <token>"
# guard 审计账：GET /api/audit?task=<id>
```

### 6.4 盯执行过程（不盯命令，看它在干嘛）

```bash
# 实时流（SSE，20 秒快照）
curl -N "http://127.0.0.1:8787/api/exploration/activity/stream?task=<id>" \
  -H "Authorization: Bearer <token>"
# 分页历史：session=plan（规划者）| intent:<id>（某条意图全过程）| main（主对话）
```

事件类型：`thinking`（思考）/`tool_use`（调了什么工具、参数全文）/`tool_result`（返回）/
`round`（第几轮规划）/`result`（阶段结论）。

### 6.5 看门狗优化：区分「发现」与「实访问」（2026-10-18 实战修正）

> **原版问题**：`domain_blacklist` 是纯子串匹配——agent 做 JS 分析时输出里出现内网域 URL
> （如前端代码引用的 `api.example.com`），就命中和**暂停整个任务**。实测误报一次。
> 内网域在「侦察发现」和「横向进入」是两回事，不能一律停机。

**改法**（改 `redline.py` 的黑名单匹配段 + `redline_rules.json`，原文件备份 `.bak`）：

```json
{
  "domain_action": "pause",                 // 实际访问构造 → 暂停（不变）
  "domain_mention_action": "alert",         // 新增：仅提及（分析输出/枚举）→ 只告警不停任务
  "domain_access_pattern": "(?i)(curl\\s|wget\\s|invoke-webrequest|iwr\\s|requests\\.(get|post|put|head|delete)|urlopen|httpx?\\..*|socket\\.(create_connection|gethostbyname)|nslookup|resolve-dnsname|test-netconnection|ncat|nc\\s+-|ping\\s|fetch\\(|xmlhttprequest|urllib\\.request)"
}
```

- 匹配逻辑：黑名单域名出现位置**±250 字符内**有访问构造（curl/requests/urlopen/socket/fetch…）→ `domain_action`（pause）；否则 → `domain_mention_action`（alert，只写 `redline_alerts.log`）。
- 五类硬规则（破坏性/凭据窃取/外联/拖库/提权）**保持 pause 不动**——那些无歧义。
- **自检**（改完必跑）：
  ```python
  from redline import RedlineEngine
  e = RedlineEngine('redline_rules.json')
  e.match({'kind':'tool_use','tool':'Bash','detail':'https://api.example.com/ <- nextjs__app.js'})  # 应仅 alert
  e.match({'kind':'tool_use','tool':'Bash','summary':'curl http://api.example.com/x'})               # 应 pause
  ```
- 改完**重启看门狗**生效（规则是启动时加载的）。看门狗误停的恢复：任务若只是 paused → `/api/tasks/<id>/control resume`；若已 timeout（终态）→ resume 会 409，只能新建任务用 `source_task_ids` 继承（见 §10）。

## 7. 结果输出（四种形态）

### 7.1 漏洞发现

```bash
curl "http://127.0.0.1:8787/api/exploration/findings?task=<id>" -H "Authorization: Bearer <token>"   # 列表
curl "http://127.0.0.1:8787/api/exploration/findings/<fid>" -H "Authorization: Bearer <token>"        # 详情（含证据）
curl "http://127.0.0.1:8787/api/exploration/findings/<fid>/lineage" -H "Authorization: Bearer <token>" # 血缘：哪个意图产出
```

### 7.2 Markdown 报告（即时生成，不落盘）

```bash
curl "http://127.0.0.1:8787/api/report?task=<id>" -H "Authorization: Bearer <token>" -o report-<id>.md
```

### 7.3 结果包（喂给本地渗透插件的标准打法）

让 DSH（或自己跑脚本）把任务结果打成一个目录：

```
artex-runs\<run-id>\
  task.json       任务元数据（状态/目标/约束/漏洞计数）
  assets.json     资产图结果（IP/服务/端口/指纹）
  activity.json   planner + worker 完整执行轨迹
  findings.json   漏洞与证据（有则生成）
  open_ports.txt  worker 自写脚本的原始产出（如有）
  scan.py         agent 自己写的工具（如有，可直接复用）
```

现成样板：`artex-runs\run-20261018-1346\`（首次联动实测包）。

### 7.4 产物目录（data）与迁移

## 10. FAQ / 故障排查

| 现象 | 处理 |
| --- | --- |
| ARTEX 起不来，提示“未找到数据库配置” | PG 没跑：`status-pg.bat`→`start-pg.bat`；或 `config.json` 被改动 |
| 页面能开但 agent 不动 | LLM 没配/Key 失效：§5.4 换配或页面「测试连接」 |
| 建任务报 “LLM 配置不存在或未设置 API Key” | `llm_profile_ids` 传了不存在的 id；不传就用激活配置 |
| agent 命令失败一片 | Windows 上 shell 是 **PowerShell**：`&&` 改 `;`、`ls` 用 `Get-ChildItem`；agent 通常会自己适配 |
| 全端口扫描期间活动流几分钟没动静 | 命令在后台跑，正常；带 `since=<最后seq>` 续看，或看 `data\tasks\<id>\i<意图id>\` 里的产出文件 |
| 看门狗误停了正常任务 | 把误报规则 pattern 改严，或该规则 action 改 `alert`；`--dry-run` 试运行 |
| MCP 调用 401 | 密码改了没同步 `ARTEX_PASSWORD`；或 JWT 7 天过期——重连 MCP 会自动重登 |
| MCP 调用 403“密码未初始化” | 先走 `/setup` 或 `POST /api/auth/init` |
| 磁盘暴涨 | 流量录制：页面「流量」页清理，或「系统设置」关流量采集 |
| 想改管理员密码 | `POST /api/auth/change-password`（旧 token + old_password/new_password，≥8 位），同步改 MCP 配置 |
| **LLM 401 `Incorrect API key`** | **端点与 key 不匹配**（实战：切 plan 端点 `step_plan/v1` 没同步换 key）。修：`POST /api/llm` 同时给 `base_url`+`api_key` → `POST /api/llm/test` 验证 ok → resume 任务。**只改端点不换 key=必 401**；任务若已因此 timeout，只能新建+`source_task_ids` 继承 |
| **worker 一片 PowerShell 语法错**（`C:\dev\null`、`At line:1 char:`） | 噪音，非故障：agent 按 bash 习惯写 `2>/dev/null`/`&&`，Windows PowerShell 报错后通常自愈（下一条命令就对）。goal 里可加一句「shell 为 PowerShell」减少 |
| **resume 报 409「状态不允许」** | 任务已被 timeout（**timeout 是终态**，和 paused 不同）。只能：新建任务 + `source_task_ids:[旧id]` 继承其资产/发现，goal 里写「继续任务 #N 的未完成工作」 |
| **timeout_seconds=0** | **不限时长**——长跑深挖用这个（实战按用户要求从 1800 改 0，跑几小时到自然完成） |
| **finding 出现了但不深挖** | ARTEX **不会自主决定深挖**（实测）：任务内靠 goal 预写或人工在 UI「主 Agent 会话」里指定；跨任务/自动接续用 §13 autofollow |
| 磁盘暴涨 | 流量录制：页面「流量」页清理，或「系统设置」关流量采集 |
